## Findings and fixes

| Finding | Impact | Change | Regression coverage |
| --- | --- | --- | --- |
| Invalid custom signup ratings silently accepted | Entering `9` created an account rated `8`. Empty input also fell back to `3.5`; values below 2 were clamped upward. The user could create an account with a different rating than requested. | Validate that the custom input is present, finite, and between 2 and 8 before converting to Elo. Show an inline error and preserve the entered value. | `permissions.spec.ts`: reject `9`, `1.9`, and blank without navigating; correct to `3.75` and verify the profile rating and preserved `/setup` return path. |
| Guest rating dropdown lacked an accessible name | Screen-reader users could encounter an unnamed selector in Add Guest. Existing accessibility checks covered other screens and missed this state. | Add explicit accessible names to the guest-name input and rating selector. | `resilience.spec.ts`: locate controls by their accessible names, run Axe on the open guest form, select rating 4, and create the guest successfully. |
| Singular roster count said “1 players on roster” | Visible polish issue immediately after creating a group. | Render “1 player on roster” and retain plural wording for other counts. | `resilience.spec.ts`: assert the singular count, add a guest, then assert “2 players on roster.” |

The new regressions were run before implementation and failed on the original
behavior. They passed after the fixes. A separate static review found no
actionable issues in the fix diff.

- Home → signup → profile → create a new public group.

  one completed session. This completed successfully.

round progression, completed summaries, score correction, match cancellation,
round undo, attendance changes, open play, PIN access, guest-account linking,

## Suggestions and remaining polish

1. **Make E2E database isolation mandatory.** The default Playwright config falls
   back from `TEST_DATABASE_URL` to `DATABASE_URL`, and can reuse any server on
   port 3000. Require an explicit test database and a dedicated test server to
   reduce the risk of future test runs using a real database. This audit avoided
   both fallbacks with the dedicated harness.
2. **Give public group names more room on phones.** At 393 px, “UX Audit 1015
   Public” was truncated to “UX Audit 1015 …” while View Group and Joined occupied
   most of the row. Consider placing actions below the name or allowing the name
   to wrap. There was no horizontal overflow.
3. **Improve the post-signup empty state.** Signup without a return path lands on
   Find a group. With no public groups, it only says “No public groups match that
   search.” A direct Create Group action and a clearer first-use message would
   help hosts discover the next step; currently they must go through My Profile.
4. **Finish singular game-count wording.** Roster entries after one scored game
   still display “1 games.” This is a remaining low-impact copy issue.
5. **Extend coverage to temporary groups and real browser engines.** The
   temporary save flow worked in this manual walkthrough, but has no dedicated
   E2E spec. Add persistence/reload, sign-in-to-save, and exit-warning coverage.
   Both current device projects use Chromium; add Safari/WebKit coverage if
   iPhone use is important.

These suggestions were not implemented as part of the focused fixes above.
This audit does not establish that the app is bug-free. Tournament brackets,
offline recovery, real-device keyboard behavior, production deployment, and
color contrast were not comprehensively tested. Axe checks retain the existing
suite's color-contrast exclusion.
